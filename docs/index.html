01 · Installation

Install once.
Use it everywhere.

D[Ai]NO is installed as an isolated command-line application. It does not add packages to the repositories you work on.

RequiredPython 3.12+
RequiredGit
Application manageruv or pipx
OptionalDocker · Node.js 18+
Terminal · recommended
# Clone and run the managed installer
git clone https://github.com/Chintan99/daino.git
cd daino
./scripts/install.sh

# Open a project in the browser IDE
cd /path/to/project
daino --gui
Terminal · from the cloned source
uv tool install .
uv tool update-shell

# Open a new terminal, then launch
cd /path/to/project
daino --gui
Terminal · from the cloned source
pipx install .
pipx ensurepath

# Open a new terminal, then launch
cd /path/to/project
daino --tui
PowerShell
git clone https://github.com/Chintan99/daino.git
Set-Location daino
uv tool install .
uv tool update-shell

# Restart PowerShell, then open a project
Set-Location C:\path\to\project
daino --gui
i

Command not found? Run uv tool update-shell or pipx ensurepath, then open a new terminal. The usual launcher location is ~/.local/bin/daino.

03 · Providers

Bring the model
that fits the work.

Provider setup lives inside D[Ai]NO. Choose a type, enter its endpoint, select a model from the live catalog, test a real generation, and save it for this project or globally.

Hosted

OpenRouter

One endpoint for hosted coding models. Paste a key in the provider form; D[Ai]NO validates it, stores it privately, and writes only a secret reference to configuration.

Base URL
https://openrouter.ai/api/v1
Capabilities
Chat · structured output · tools
Local · recommended

Ollama

Run coding models fully on your machine. D[Ai]NO reads Ollama's installed-model catalog, needs no API key, supports native tools, and serializes requests by default for reliability.

Base URL
http://127.0.0.1:11434/v1
Capabilities
Chat · structured output · tools
Local / self-hosted

vLLM

Connect an OpenAI-compatible vLLM server for larger local or remote deployments. Structured output works directly; native tools are enabled when the server has a tool-call parser.

Base URL
http://127.0.0.1:8000/v1
Capabilities
Chat · structured output · optional tools
Custom

OpenAI-compatible

Use a private gateway or another service implementing the OpenAI chat API. Configure the base URL, model id, and a secret reference; D[Ai]NO tests the endpoint before use.

Base URL
Your endpoint ending in /v1
Capabilities
Chat · structured output

04 · The coding loop

Evidence, not optimism.

01

Understand

Indexes the repository, ranks relevant files and symbols, and reads exact source only when needed.

02

Change

Applies scoped edits to the working tree after taking a recoverable checkpoint.

03

Verify

Runs tests, linters, builds, and policy-gated commands. Failed evidence must be resolved.

04

Review

Shows the full diff and can route it to an independent reviewer before completion.

CODE

Your repository, fully in view.

Use D[Ai]NO as an editor and as an agent without losing the connection between a request, the source, and the resulting diff.

Explore and edit

Browse files with Git status markers, search across the project, open symbols, and edit in Monaco with tabs, dirty state, save, find, formatting, and language-aware navigation.

Run and diagnose

Open real PTY terminals, switch shells, and use the Problems, Tests, and Output panels. Preview commands and approvals remain attached to the same session.

Review safely

Inspect staged, modified, and untracked files. A side-by-side Monaco diff shows working tree versus index or index versus HEAD before you keep or restore anything.

Give precise context

Attach the active file, selected lines, terminal output, or a Git diff to the composer. The agent panel stays available while you navigate and edit.

DESIGN

Sketch, prototype, and edit visually.

A structured canvas for architecture and UI work. Manual edits and agent edits update the same versioned artifact.

Work with the agent

The open page or selected node enters context automatically. Ask for a change and the preview updates when it lands, with conflict choices if your own edits are unsaved.

Move from idea to code

06 · Capabilities

One agent system,
end to end.

A

Agent workflow

  • Questions and editsOne prompt surface decides whether the request needs explanation or action.
  • Agent shellTests, linters, builds, and inspection feed back into the coding loop.
  • Web researchPublic sources through explicit network approval and bounded fetching.
  • QA workspaceDeterministic checks plus parallel read-only architecture, security, quality, and UI reviewers.
M

Missions and teams

  • Durable missionsRequirements, approval-gated plans, isolated worktrees, verification, review, and evidence.
  • Parallel teamsDependency waves with non-overlapping write scopes and read-only specialists.
  • PlaybooksVersioned procedures with declared tools, gates, checks, and rollback steps.
  • RecoveryCheckpoints, restore previews, resumable state, retry, cancel, and discard controls.
C

Context and memory

  • Repository intelligenceSymbols, references, routes, tests, databases, dependencies, and entry points.
  • DAINO.md instructionsGlobal, repository, and directory-scoped guidance follows the files being edited.
  • Durable memoryUnfinished work, verified facts, decisions, failures, episodes, and preferences remain local.
  • Budgeted contextExact files and symbol windows are ranked against each model's real context limit.
O

Models and operations

  • Provider-independentOpenRouter, Ollama, vLLM, and OpenAI-compatible endpoints.
  • Role routingDifferent models for architecture, planning, building, review, debugging, testing, and deployment.
  • Local or Docker runtimeHost toolchains or isolated containers under the same command policy.
  • Ship safelyCompose releases, health-gated rollback, Terraform/OpenTofu controls, logs, stats, and audit events.
07 · Safety model

Autonomy with visible boundaries.

Every interface uses the same policy engine. Model output is validated before execution, file writes stay inside the project, and secret values are resolved only at the provider or SSH boundary.

Read the security model →
PLAN

Read-only exploration and task planning.

ASK

Routine work runs; sensitive commands ask first.

SESSION

Approved command categories stay allowed for this conversation.

FULL

Mission gates continue automatically; hard denials still apply.
